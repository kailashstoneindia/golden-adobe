How brands are connected to products

A brand owns its products through master_product.brand_id. Everything else in onboarding (spellings, merges, duplicate checks, imports) hangs off that link.

One brand, many products

A branded product points at exactly one brand. A generic product (loose stone, unbranded hardware) has no brand, and the database forbids giving it one.

Part numbers are per brand

(brand_id, mfr_part_number) is unique. Two brands may both sell "MCB-10"; one brand cannot have it twice. This is the main duplicate check on import and edit.

One brand, one name

Brand names are unique after normalising: "HAVELLS", "Havells Ltd" and "Havells India" are the same brand. Other spellings live in brand_alias, each owned by one brand only.

Merged, not deleted

Merging a duplicate brand moves its products and aliases to the one that stays. The old row is kept, deactivated, with merged_into_id, so its old name still finds the right brand.

Compliance lives on the brand

Manufacturer name and address and consumer-care contacts are stored once per brand and shown on every one of its products (Legal Metrology, decision 0010).

Vendors sell, the platform owns

Vendors never create brands or products. They add a listing (price, stock, grade) on a catalog product. A product can go live before any vendor lists it.

Brand name matching

Any spelling finds the right brand

Every place a brand is typed (spreadsheet import, add-product, a vendor's row in the review queue) goes through the same resolver. Try a spelling below.

    Example catalog for this demo: Havells (also spelled "havells india ltd", "h.i.l"), Polycab, "Havels Old" (merged into Havells), "Retired Co" (deactivated). The name rule matches the database's own normalize_brand_name(): lowercase, spaces collapsed, one trailing "Pvt Ltd", "Ltd", "Limited", "India" or "Electricals" removed.

    Onboarding a brand, step by step

    STEP 1

    Add the brand

    Catalog › Brands › Add brand
    • Name plus the four compliance fields, checked as you type (email shape, phone pattern).
    • A name that matches an existing brand after normalising, or another brand's spelling, is refused and the existing brand is named.
    • Open the brand to upload a logo (JPEG, PNG or WebP, up to 2 MB) and add other spellings.
    • Deactivate a brand to stop new products using it; its existing products are untouched.
    STEP 2

    Give the category a default HSN code

    Catalog › Categories › pick a category › Set default
    • Optional. New products in the category (or a sub-category without its own default) start with this HSN code and its GST rate.
    • Missing HSN codes can be added from the picker (4 to 8 digits, rate 0 to 100).
    • The panel says where a default comes from, for example "8536 (from Electrical)".
    STEP 3A

    Add one product through the form

    Catalog › Products › New product
    • Pick a leaf category: a field appears for each of its attributes; starred ones are needed to publish.
    • Pick the brand (or add one without leaving the form). HSN code and GST rate are pre-filled from the category default.
    • Save the draft, add at least one image, and the checklist turns green. Publish stays disabled until then.
    STEP 3B

    Or import a spreadsheet

    Catalog › Import
    • Choose the category, download its template, fill it, upload it (.xlsx, up to 20 MB).
    • The import runs in the background. The page shows "120 of 400 rows", then the accepted and rejected counts.
    • Brands in the sheet are matched by any spelling. Each valid row becomes a draft product stamped with its import.
    STEP 4

    Fix the rejected rows

    Catalog › Import › Past imports › Download rejected rows
    • The download is the same sheet with only the rejected rows and an import_errors column saying what is wrong.
    • Typical fixes: add the missing brand, pick a value from the dropdown, correct a duplicate part number.
    • Upload the fixed file on its own: rows already imported are not touched again.
    STEP 5

    Upload the pictures in bulk

    Catalog › Products › Upload images
    • Name each file by product code (GA-0110919.jpg) or by the brand's part number (MCB-10.jpg); _2, _3 for more pictures.
    • The preview shows the product each file goes to, "Will become primary" for a product with no picture yet, or why a file is skipped.
    • Uploads run four at a time, each with its own result.
    STEP 6

    Publish the brand's drafts

    Catalog › Products › Brand filter › Draft
    • "Publish all drafts of brand" publishes every draft that is ready.
    • Drafts that are not ready are listed with their product code and what they still need, for example "needs at least one image".
    • A single product can also be published from its popup; the button stays disabled while something blocking is missing.
    Publishing rules

    What a product needs before it goes live

    The same four checks drive the checklist on screen, the Publish button, single publish and publish-by-brand. Toggle them to see what an admin would see.

    Example product: a modular switch whose starred attribute is "Finish".

    Ready to publish?

      Blocking

      An image (not a spec sheet, not a failed upload) and every starred attribute. Publishing without them is refused, also through the API.

      Warning only

      HSN code (needed once invoices exist) and an active vendor listing. The product can go live without them.

      Duplicates

      A product identical to a live one (same category and starred attribute values) is refused with "a product with the same category and attribute combination already exists". Merge it instead.

      Fixing mistakes

      Every mistake has a way back

      Nothing that a vendor or customer depends on is ever deleted. Products are retired or merged; brands are deactivated or merged.

      MistakeWhereWhat happens
      Wrong brand, part number, GTIN, HSN code, originProduct popup › EditOnly changed fields are saved. Duplicates are refused with a clear message. Category, product code and slug never change.
      Product should not be soldProduct popup › RetireStatus becomes Retired and its active vendor listings are paused in the same step. Restore brings it back as a draft.
      Draft made by mistakeProduct popup › DeleteOnly a draft with no listing, order or vendor import row; otherwise "retire it instead". Its images are removed too.
      The same product twiceProduct popup › Merge into…Listings, vendor codes and (if needed) images move to the kept product; the extra one is retired and points at it.
      The same brand twiceBrands › Merge into…Products and spellings move to the kept brand; the old name becomes another spelling. Refused if both brands use the same part number.
      A whole upload was wrongImport › Past imports › UndoDeletes the import's untouched drafts, reports what was kept.
      A vendor's row matched nothingReview queue › Create product from this rowThe form opens with the vendor's name, brand and reference; after saving, the row is linked so the vendor's code matches next time.
